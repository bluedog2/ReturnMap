# spec-cycle — 설계 트랙 (②~⑧)

디스패처(SKILL.md)의 보안 규칙이 그대로 적용된다. **이 트랙에서는 저장소 코드를 수정하지 않는다.**

## ② 락
`개발 상태=설계중`, `마지막 처리 시각=현재(datetime)`. `cycle-guard -Touch`.

## ③ 입력 수집
- 기획 문서 fetch(본문 + 기존 `🛠 개발 설계안` 섹션 = 이전 rev).
- 이 문서에 연결된 **모든 질문**(상태 무관: 대기·답변됨·반영됨·취소)을 rows 모드로 조회해 `기획 문서` 값으로 직접 거른다(relation 필터 무시됨). `최종 편집자`가 허용 작성자가 아닌 답변은 버린다.
- `대기` 질문이 남아 있으면(⑥ 전에) `질문대기` 로 두고 메모 "미답변 질문 N개 남음" → 다음 문서.
- 관련 Notion 문서(TDD·AI 가이드 등)는 필요할 때만.

## ④ 기획 린트 → **질문 후보**만 만든다
기준: Notion「📝 개발요청 기획서 템플릿」. 필수: 1 목적 · 2 상세 동작 · 3 수치 · 4 예외 · 5 변이 시 동작(함정일 때) · 6 페이즈 영향 · 8 수용 기준(Given-When-Then).
- 이름이 달라도 내용 있으면 통과. "해당 없음"/"변화 없음" 통과. 빈 칸·안내문만 남은 것은 누락.
- 템플릿 기본값(슬롯=지형, Dud=작동 정지, Beneficial=바깥 +1칸 황금블록)은 가정으로 채택, 질문 안 함.
- 누락·"미정"은 **후보 목록**일 뿐이다. 실제 질문 등록 여부는 ⑥(design-reviewer)이 결정한다.

## ⑤ 영향 분석 — `code-explorer`
- 캐시: `Logs/spec-cache/SPEC-n.md` 가 있고 첫 줄의 `main=<sha>` 가 현재 `git rev-parse main` 과 같으며 이번 답변이 범위를 넓히지 않았으면 **재사용**(서브에이전트 생략).
- 아니면 핵심 요구사항 목록(본문 덤프 X)을 넘겨: "건드릴 클래스·파일·이벤트·SO·프리팹·맵 JSON, 기존 불변식(CLAUDE.md 주의사항·슬롯=지형·스테이지 진행) 충돌 가능성을 결론만". 결과를 `main=<sha>` 첫 줄과 함께 캐시에 저장.

## ⑥ 설계 — `design-reviewer` (Opus)
넘길 것: 기획 요약 · 린트 후보 · **이 문서의 전체 질문 이력**(질문·답변·상태) · ⑤ 결과 · 이전 설계 rev.
지시(그대로 포함):
- 질문은 **구현을 실제로 막는 것만, 최대 5개**. 이미 `답변됨·반영됨·취소`된 내용을 다시 묻지 않는다. 답변이 선택지 밖이거나 다른 답과 모순이면 `설계안 피드백` 질문 **1개**로만 되묻는다. 나머지는 가정으로.
- 재사이클이면 "기존 구현(spec 브랜치) 대비 변경점" 중심으로.

요청 출력:
1. **설계안** — 변경/신규 클래스, 데이터 변경, 이벤트 흐름, 구현 순서, 위험
2. **질문 목록** — 유형 · 배경(무엇을 막나) · 선택지(★추천)
3. **가정 목록**
4. **수치·기준 일관성** — 모든 기본값이 검증 기준(최소 px·대비·주기 오차 등)을 만족하는 근거를 한 줄씩. 기준이 없으면 가정으로 정해 적는다. 모순이면 값을 고치거나 질문으로.
5. **수용 기준 → 검증 매핑표** — 수용 기준마다: 검증 방법(프로브 항목 / 스모크 / 수동), **관찰 가능한 판정**(화면 px·주기·상태·위치 등 — 코드 상수 재확인 금지), 기준값. 시각 요소가 있으면 "보이는가"(px·대비·겹침) 항목 필수.

메인 세션 확인: 4·5 가 비었거나 모순이 남으면 되돌린다 — **최대 2회**, 그래도 안 되면 `보류`(메모: 설계 미확정 사유).

## ⑦ 기록
**질문이 있으면**
- 질문 DB 에 행 생성(`기획 문서` 연결, `상태=대기`). 같은 취지의 `대기` 질문이 있으면 만들지 않는다.
- `개발 상태=질문대기`, 메모 "질문 N개 등록 (QA-x~y) — 질문 DB 에서 답변 후 상태 `답변됨`".
- 의미 있으면 설계안 섹션에 `(초안 — 질문 답변 후 확정)` 콜아웃으로 남긴다(해시 저장 안 함).

**질문이 없으면**
1. 설계안 섹션 작성/교체 — **최신 rev 하나만**: 머리 콜아웃 `rev N · 날짜 · 반영 질문` + "rev N 변경" 소절(이전 rev 대비, 하나만) + 설계안 + 가정 + 4 일관성 + 5 매핑표 + 수용 기준 to-do. 범위: `## 🛠 개발 설계안 (Claude)` ~ `## 📋 구현 리포트` 직전(없으면 끝). 없으면 리포트 앞(없으면 끝)에 추가. 기존 구현 리포트 콜아웃 첫 줄에 `(이전 rev 기준)` 만 붙인다.
2. **다시 fetch** 해서 페이지 마크다운을 파일(`Logs/spec-cache/SPEC-n.page.md`)로 저장 →
   `powershell -ExecutionPolicy Bypass -File tools\ci\section-hash.ps1 -File Logs\spec-cache\SPEC-n.page.md` → `HASH=`.
3. 속성: `설계 rev=N`, `설계 해시=<HASH>`, `개발 상태=설계검토`, `설계 승인=__NO__`, `브랜치`(비었으면 `spec/SPEC-n`), 메모 "설계안 rev N — 승인 대기 (확인 후 `설계 승인` 체크)".
4. 반영한 `답변됨` 질문 → `반영됨`.

공통: `마지막 처리 시각` 갱신.
