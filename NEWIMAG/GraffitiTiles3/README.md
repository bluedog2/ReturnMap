# Re:Trap 낙서 Wang 타일 3차

2차본의 최종 32×32 그림을 직접 재사용했다. 새 이미지 생성, 선·도형 그리기는 하지 않았다. 변경은 콘크리트 단면 교체, 외곽 잔재 정리, 기존 띠 단면 복사, 배치 규칙 변경이다. 2차본과 다른 폴더는 읽기만 했으며 git은 사용하지 않았다.

## 경계 줄 원인과 수정

2차 조립은 Floor1의 원본 x=0 외곽을 단면으로 사용했고, 0번과 2번은 Floor00 x=2를 사용했다. 서로 다른 바탕색과 차콜 외곽선·균열이 표준 단면에 섞였다. 이를 경계 양쪽에 2px씩 복사하면서 일부 경계에 4px의 어두운 띠가 생겼다. 특히 Floor1 콘크리트 단면 밝기는 69.222로 내부 평균 약 105보다 크게 낮았다. Wall도 종류별 별도 원본 행의 바탕과 외곽 잔재가 달랐다.

3차는 Floor00 내부 x=6 열, Wall00 내부 y=4 행을 공통 바탕으로 재사용한다. 단면의 어두운 외곽/균열 픽셀은 같은 행/열의 인근 내부 콘크리트 픽셀로 교체한다. 기존 2px 단면 바로 안쪽 2px에 남은 어두운 외곽 잔재도 콘크리트 구간에 한해 정리했다. 낙서 포트와 Floor 상단 3px는 보존한다.

보존한 띠 구간(0부터): Floor1 y=12..21, Floor2 y=14..21; Wall1 x=12..20, Wall2 x=13..18. 주 색 띠뿐 아니라 인접 차콜 테두리까지 복사했다. 최종 표준 단면 RGBA는 `Edges/profiles.txt`에 있다.

## 새 배치 규칙 — 게임도 동일하게 적용

```text
h = uint32(x*73856093) XOR uint32(y*19349663)
h ^= h >> 13
h = uint32(h * 0x5bd1e995)
h ^= h >> 15
r = h % 4
kind = r < 2 ? 0 : r - 1
```

0,1 → 0(없음), 2 → 1(크림슨), 3 → 2(흰색). 이론 경계 분포는 없음 50%, 크림슨 25%, 흰색 25%다. 부호 없는 32비트 overflow wrap과 logical shift를 사용한다.

Floor: 같은 지형의 인접 타일 사이 E(x,y)=kind(x,y), 나머지 0. L=E(x-1,y), R=E(x,y).
Wall: 위쪽 같은 지형 사이 V(x,y)=kind(x,y), 나머지 0. T=V(x,y), B=V(x,y-1). 맵 y는 위로 증가한다.

1-1 또는 2-2 타일은 타일 좌표의 `(h >> 8) & 1`이 1이면 `_b`, 0이면 기본 파일(논리 a)을 선택한다. 이 비트는 포트 종류를 바꾸지 않는다. `GraffitiTiles3Placement.cs`는 게임에 사용할 동일 규칙의 C# 참조 구현이다. 쓰기 범위 제한에 따라 Assets 게임 코드에는 설치하지 않았다. 조립 코드의 Strip·Mock에는 이미 이 규칙을 적용했다.

`_b`는 00 콘크리트에 기존 띠 단면 조각을 반복 복사한 모티프 없는 변형이다. 기본 00은 2차의 금·얼룩 콘크리트를 유지하며 별도 00 변형은 추가하지 않았다.

## 출력과 재현

- `_1x/`: Floor 기본 9 + b 2, Wall 기본 9 + b 2 = Play 22장.
- `_1x/Build/`: 동일 22장, 2차와 같은 청회색 치환. 총 44장, 모두 32×32 RGBA.
- `Edges/`: Floor/Wall 각 3종, 정확한 단면 색 목록.
- `Sheet_Floor_6x.png`, `Sheet_Wall_6x.png`: 기본 3×3 + 하단 b 변형 2개. 580×774. 시트 셀 사이 2px 검정은 시트 여백이며 타일에 포함되지 않는다.
- `Strip_3x.png`, `Strip_Build_3x.png`: 24칸×3줄, y=0,7,19. 2304×336.
- `Strip_Wall_3x.png`: x=0,7,19, 위아래 끝 포트 0. 336×2304.
- `Mock_3x.png`, `Mock_Build_3x.png`: stage_01, trapSlots 4개, Hero_Idle 첫 프레임, 스폰 (2,1). 이전과 같은 카메라 x=[0,640), y=[0,360), 발 위치 y=328. 1920×1080.
- `Compare_3x.png`: 2차 원본 Mock 위, 3차 Mock 아래. 1920×2256.
- `Compare_Strip_3x.png`: 2차 y=0 원본 Strip 위, 3차 y=0 아래. 2304×288.
- `Sources/`: 비어 있음. 새 생성이 없으므로 2차 원본을 중복 저장하지 않았다.
- `assemble.cs`, `rebuild.ps1`, `GraffitiTiles3Placement.cs`, `strip_sequence.txt`, `validation.txt`.

저장소 루트에서 `powershell -NoProfile -File NEWIMAG/GraffitiTiles3/rebuild.ps1` 실행. System.Drawing이 있는 Windows PowerShell을 사용한다. 재현 입력은 GraffitiTiles2/_1x, Edges, Mock, Strip, 두 허용 팔레트, stage_01 JSON, Hero_Idle이다.

## 검증

밝기는 Rec.709 가중 RGB 값 Y=0.2126R+0.7152G+0.0722B(0..255)로 계산한다. 콘크리트 내부 기준은 경계 방향 d=4..27의 따뜻한 중성색 픽셀이다. 낙서·차콜 외곽·깊은 균열은 콘크리트 평균에서 제외한다. 정확한 마스크는 `!Paint(c) && R>=80 && abs(R-G)<35`; Floor 상단 표면·그림자는 y<7이므로 제외한다. 경계 측정은 띠 구간을 제외한 양쪽 2px 전체다. 00과 b를 포함해 가능한 41개 연결 조합씩 Floor/Wall 모두 검사했다.

- 모든 Play 연결의 경계/내부 평균 차이 절댓값 최대 **5.474%**, ±6% 통과.
- 단면 콘크리트 138개 위치 중 Y<75인 차콜 픽셀 **0개**. 검은 경계 띠 없음.
- Play/Build, Floor/Wall, a/b 전체 경계 RGBA **10,496/10,496 = 100%**.
- 타일당 최대 **19색**, 허용 두 팔레트의 합집합 안에 있음. 알파 모두 255.
- Build 22장 모두 Play와 픽셀 좌표가 같은 2차 청회색 치환인지 검사했다.
- Strip 72칸의 완전히 빈 00은 **19/72 = 26.389%**. 내부 경계의 없음은 **35/69 = 50.725%**. 양끝 강제 0은 이 경계 분모에서 제외했다. b는 4/72칸이다.

50%는 경계 종류 확률이다. 완전히 빈 타일은 양쪽이 모두 0이어야 하므로 50%를 뜻하지 않는다. 모든 연결별 수치는 validation.txt에 있다.

## 한계

경계의 어두운 프레임은 제거했지만 원본 모티프·금·얼룩은 반복된다. 특히 00의 긴 반복에서 같은 균열이 눈에 띌 수 있다. b는 기존 단면을 복사해 띠가 곧고 질감 변화가 적다. 서로 다른 타일 내부의 금 모양과 낙서 곡선 기울기까지 연속적이지는 않다. 밝기 수치는 위에 명시한 콘크리트 마스크 기준이며 모든 아트 픽셀의 평균이 아니다. 게임 런타임 설치·플레이 검증은 수행하지 않았다.
