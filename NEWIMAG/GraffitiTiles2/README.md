# Re:Trap — 굵은 스프레이 Wang 타일 2차

1차본의 Wang 경계 방식·해시·맵 배치·카메라를 유지한 2차 리소스다. 그림은 built-in image_gen으로 만들었다. 코드는 블록 중앙 샘플, 허용 팔레트 치환, 원본 사각 조각 합성, 2px 표준 단면 복사, 기존 캐릭터/맵 합성과 비교용 라벨에만 사용했다. 1차본과 다른 폴더는 수정하지 않았고 git은 사용하지 않았다.

## 파일 목록

- `_1x/Floor_L{0..2}_R{0..2}.png`: Play 바닥 9장, 각각 32×32.
- `_1x/Wall_T{0..2}_B{0..2}.png`: Play 벽 9장, 각각 32×32.
- `_1x/Build/`: 같은 이름의 청회색·저채도·저대비 팔레트 변형 18장.
- `Edges/`: Floor_0..2, Wall_0..2 표준 단면 6장과 `profiles.txt`의 정확한 RGBA 색 정의.
- `Sheet_Floor_6x.png`, `Sheet_Wall_6x.png`: 580×580, 행=입구 종류, 열=출구 종류, 최근접 6배.
- `Strip_3x.png`, `Strip_Build_3x.png`: 2304×336, 24칸×3줄, y=0,7,19. 양 끝 종류 0.
- `Strip_Wall_3x.png`: 336×2304, x=0,7,19, 위·아래 바깥 종류 0.
- `Mock_3x.png`, `Mock_Build_3x.png`: 1920×1080, stage_01과 주인공, 1차와 같은 카메라.
- `Compare_3x.png`: 1920×2256. 위는 1차 Mock 원본, 아래는 2차 Mock 원본. 라벨은 “1차: 가는 선” / “2차: 굵은 스프레이”.
- `Sources/`: 채택한 Floor/Wall 원본, 미채택 원본 5장, 전체 프롬프트 `prompts.md`. 모두 재현·비교용 영구 자료다.
- `assemble.cs`, `rebuild.ps1`, `sampling.txt`, `strip_sequence.txt`, `validation.txt`.

저장소 루트에서 `powershell -NoProfile -File NEWIMAG/GraffitiTiles2/rebuild.ps1`로 재구성한다. 원본은 모두 이 폴더에 보관하므로 CODEX_HOME에 의존하지 않는다.

## 그림과 팔레트

바닥 3회 생성 중 3번째, 벽 4회 생성 중 4번째를 채택했다. 큰 왕관·X·화살표·RE/TRAP·별·이빨 모티프를 따뜻한 회갈색 콘크리트 위에 배치했다. A안의 색감·금·얼룩을 따른 새 원화이며, 바닥 y=0..2는 A안 Tile_Play_Floor 원본 조각을 재사용한다. 그 세 행은 9장 모두 픽셀 단위로 동일하다.

허용 색은 `NEWIMAG/palette_v2.txt`와 `NEWIMAG/TileConceptV2/A/palette_add_A.txt`의 합집합이다. 최종 36장 모두 알파 255, 최대 19색. Build는 1차와 같은 좌표 보존 팔레트 변환으로 저채도 청회색이며 Play와 같은 실루엣이다. 낙서의 흐림은 색 대비를 낮춘 효과로, 공간 블러를 적용하지 않았다.

## 단면 실측과 합성

좌표는 0부터. Floor는 y, Wall은 x 방향으로 단면 두께를 잰다. 표의 두께는 주 띠의 연속 페인트 픽셀 수이며 차콜·주변 튐을 제외한다.

| 종류 | Floor | Wall |
|---|---|---|
| 0 | 깨끗한 Floor00 x=2 단면 | 깨끗한 Wall00 y=2 단면 |
| 1 크림슨 | **8px**, y=13..20 | **7px**, x=13..19 |
| 2 흰색 | **3px**, y=15..17 | **4px**, x=14..17 |

Floor1 단면은 Floor10의 x=0 원본 열에서 가져왔다. Floor2 단면은 Floor22 x=3의 y=14..21 조각과 Floor00 x=2의 나머지 콘크리트를 합성했다. 모든 단면의 윗면 3행은 Floor00 x=2에서 동일하게 복사한다. Wall은 각각 Wall00/11/22의 y=2 행이다. 이 1px 단면을 두 번 복사해 각 경계 2px를 만들고, 같은 종류의 양 끝에 그대로 붙인다. 색 배열은 `Edges/profiles.txt`가 최종 기준이다.

Floor11의 E와 오른쪽 띠 사이에 생성된 차콜 공백은 Floor10의 (x=0,y=13,w=3,h=8) 원본 조각을 (x=24,y=13)에 붙여 연결했다. 선을 그리거나 픽셀을 팽창시키지 않았다.

## 낙서 크기·밀도 검사

폭 점유율은 **페인트가 하나 이상 있는 열 수 /32**다. 단순 bounding box보다 엄격하며, 칠한 면적 비율과 구분한다. 크림슨·아이보리 색만 세고 차콜 외곽선은 제외한다. Floor는 윗면과 원화의 밝은 모서리 흘러내림을 제외하려고 y<7을 검사에서 뺐다.

- 비영 경계가 있는 Floor 8장: 폭 **93.75–100%**, 면적 29.30–40.92%.
- 비영 경계가 있는 Wall 8장: 폭 **81.25–93.75%**, 면적 29.10–50.59%.
- 00 두 장: 검사 영역 페인트 0%.
- 페인트 bounding box 높이: Floor 21–24px, Wall 26–32px. 개별 중심 모티프와 연결 포트·튐을 합친 값이다.
- 단면을 넘어 이어지는 비영 포트 조합 4개×2세트: 8방향 페인트 연결 경로 **8/8 통과**.

경계는 세트당 27쌍×32×2 = 1,728개 RGBA 픽셀을 대조한다. Play Floor/Wall, Build Floor/Wall 각각 **1,728/1,728**, 합계 **6,912/6,912 = 100%**. 타일별 수치는 `validation.txt`에 기록했다.

## 배치 규칙·목업

1차의 unsigned32 해시를 그대로 쓴다. 곱셈은 overflow wrap, 오른쪽 shift는 logical이다.

```text
h = uint32(x*73856093) XOR uint32(y*19349663)
h ^= h >> 13
h = uint32(h * 0x5bd1e995)
h ^= h >> 15
kind = h % 3
```

Floor: 인접한 같은 지형의 솔리드 사이만 E(x,y)=kind, 나머지는 0. L=E(x−1,y), R=E(x,y).
Wall: 위쪽 같은 지형 사이만 V(x,y)=kind, 나머지는 0. T=V(x,y), B=V(x,y−1). JSON y는 아래에서 위로 증가한다.

`Assets/StreamingAssets/Maps/stage_01.json`의 25×14 grid와 trapSlots 4개를 사용한다. Ceiling은 1차와 같이 Floor 시각을 재사용한다. 카메라는 월드 x=[0,640), y=[0,360), 화면 y=360−월드y. 주인공은 Hero_Idle 첫 96×96 프레임, 스폰 (2,1), 발을 화면 원본 y=328 바닥에 맞췄다. Build에서도 주인공은 같은 원본이다.

## 한계

- image_gen에 처음부터 32×32 논리 격자의 블록 픽셀아트를 요청했지만 실제 반환은 1254×1254이며 격자가 완전히 일정하지 않다. 3×3 셀을 각각 32×32로 중앙 샘플링했다. 미세 번짐 일부는 사라졌으며 정확한 k배 원화라는 조건은 충족하지 못했다.
- 위의 6–10px/3–5px 범위는 **최종 표준 연결 띠**에서 충족한다. 내부 모티프의 교차점·끝부분·흘러내림은 두께가 달라지며, 모든 내부 획이 해당 범위이거나 모든 외곽선이 정확히 1px임을 보장하지 않는다. 스프레이 번짐·흘러내림도 모든 부분에서 2–4px로 일정하지 않다.
- 0 경계에서는 단면을 깨끗하게 끝내므로 일부 원화의 넓은 띠 끝이 급하게 잘려 보인다. 모든 0 끝이 자연스러운 점진적 테이퍼로 생성되지는 않았다.
- 경계 픽셀과 페인트 경로는 일치하지만, 곡선 기울기와 균열 방향은 모든 조합에서 연속적이지 않다. Floor↔Wall 코너 연결 타일은 없다.
- 각 9종을 반복 사용하므로 같은 모티프가 재등장한다. 게임 내 임포트·런타임 적용은 하지 않았다.

별도 임시 파일은 남기지 않았다. image_gen의 CODEX_HOME 원본은 허용된 생성 위치에 유지하고, 프로젝트용 사본은 모두 Sources에 보관했다.
