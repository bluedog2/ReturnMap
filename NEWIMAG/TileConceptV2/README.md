## 생성·합성 방식

참조 `ref_concept.webp`, `ref_pixelstyle.webp`, `ref_logo.png`, 승인된 `Hero_Idle.png` 및 기존 타일 구조를 열어 확인했습니다. 기존 타일의 남색 던전 색감은 사용하지 않았습니다. 이미지 생성은 내장 image_gen만 사용했습니다. 선·도형으로 재료나 낙서를 코드 생성하지 않았습니다.

기본 요청은 32×32 타일 4개를 2×2 격자에 배치하고, 64×64 논리 이미지를 정확히 16배 확대하여 1024×1024로 만드는 형식입니다. 원본 좌상 Floor / 우상 Wall / 좌하 Ceiling을 사용했습니다. 우하의 보조 재료 이미지는 납품 타일에 포함하지 않았습니다.

후처리는 각 32×32 목표 블록 중심 샘플, 기본 팔레트 정리, 페이즈별 팔레트 치환, 연결 방향의 1픽셀 경계 띠 복사, 타일 반복 붙이기와 주인공 합성만 수행했습니다. Floor·Ceiling은 오른쪽 끝 열을 왼쪽 끝 열과 맞췄고, Wall은 마지막 행을 첫 행과 맞췄습니다. 이는 기본 반복 이음매를 맞추는 작업이며 모든 방향의 코너·자동 타일 규칙을 만든 것은 아닙니다.

모든 목업은 Floor 20칸×2줄(y=296,328), Floor 5칸짜리 공중 발판(y=168: 바닥보다 4칸 높음), Wall 1칸 폭 기둥(x=544, 6칸 높이), Ceiling 7칸(x=0..192, y=8)입니다. 주인공은 첫 96×96 프레임을 원배율로 사용했고, 알파가 있는 최하단 픽셀의 아래 경계와 바닥 윗면 y=296을 일치시켰습니다. 배경은 단색입니다.

## 한계 및 미충족 항목

- 생성기를 안마다 3회 호출했지만, 요청한 1024×1024 / 정확한 16배 블록 격자를 얻지 못했습니다. 채택 원본은 1254×1254이며 내부 픽셀 간격도 불규칙합니다. **원본 격자 조건은 미충족**입니다. 중앙 샘플링 결과가 정확한 32×32라는 사실이 원본 격자의 통과를 뜻하지 않습니다.
- 그래서 일부 작은 낙서·볼트·이빨 형태는 샘플링 과정에서 단순화됩니다. 스타일 승인 이후 실제 제작 단계에서는 정수 격자 원본과 더 정교한 경계 검수가 필요합니다.
- B 3회차는 요청문 전달 과정에서 테마 본문이 빠져 일반 타일 모음이 생성되어 제외했습니다. 실제 요청문과 제외 원본을 보존했습니다.
- C 3회차도 격자 조건을 충족하지 못했고, 이빨 띠가 Floor 하단·Ceiling 상단으로 이동했습니다. 걷는 면과 천장 아랫면의 표식이 더 명확한 2회차를 채택했습니다.
- 단일 Floor/Wall/Ceiling 반복이므로 왕관·경고 띠·이빨의 반복 주기가 눈에 띕니다. 변형 타일, 코너, 내부 채움 전용 타일, 충돌 및 Unity 임포트 설정은 이 컨셉 단계에 포함되지 않습니다.
- 가로·세로의 지정 연결 경계는 수치상 일치합니다. 서로 다른 종류의 접합부까지 완전한 자동 타일 세트로 검증한 것은 아닙니다.

저장소 쓰기는 `NEWIMAG/TileConceptV2/`에 한정했습니다. image_gen 자체 원본은 허용된 Codex 생성 이미지 위치에도 남아 있습니다. git은 사용하지 않았습니다.
