# 주인공 애니메이션 계획 V4 (2026-11-05)

배경: 이동 6→8칸/초, 대시 18→24칸/초·0.21초(약 5칸)로 바꾸면서 기존 시트(3칸 전환 때 만든 V3)가 속도와 안 맞는다.
V3 의 남은 결함(Run 머리가 Idle 보다 2~5px 큼, Hit 높이 흔들림)도 같이 정리한다.

## 프레임 수보다 fps·키포즈가 먼저

- 픽셀아트는 프레임을 늘린다고 부드러워지지 않는다. 프레임마다 실루엣이 조금씩 달라지는 위험(크기 드리프트)만 커진다 — V3 가 4번 다시 그려도 머리 크기가 안 맞은 이유.
- 체감은 **동작 속도와 재생 속도가 맞는지**가 좌우한다. 달리기가 미끄러져 보이는 건 프레임이 적어서가 아니라 fps 가 낮아서다.
- Run 계산(8칸/초): 8프레임 한 주기 = 두 걸음.
  - 12fps → 주기 0.67초 → 한 걸음 2.7칸(85px). 몸 96px 에 보폭 85px 는 발이 크게 미끄러진다.
  - **18fps → 주기 0.44초 → 한 걸음 1.8칸(57px)**. 키의 0.6배 — 달리는 보폭으로 자연스럽다.
- 그래서 **프레임은 거의 그대로 두고 fps 를 속도에 맞춘다**. 늘리는 건 동작에 키포즈가 빠진 곳만(JumpStart·Dash·Hit 각 1장).

## 크기 맞추기 (V3 실패 원인 대응)

- **머리는 그리지 않고 Idle 첫 프레임 머리(얼굴·앞머리·포니테일 전체)를 그대로 붙인다.** V3 는 얼굴만 붙여서 생성된 앞머리가 남아 머리 bbox 가 커졌다. V4 는 생성 결과에서 목선 위를 전부 지우고 Idle 머리를 목 위치에 맞춰 얹는다(승인된 픽셀 합성 — 새로 그리는 게 아님).
- 몸·팔·다리·상자·신발은 GPT(image_gen)가 그린다. 코드로 모양을 그리지 않는다.
- 통과 기준: 선 자세 프레임 키 = Idle ±1px, 머리 bbox = Idle 과 동일, 바닥 행 127, 알파 0/255, 24색 이하, 가로 중심 ±2px.
  예외(높이): JumpStart 웅크림, Dash 기울기, Hit 젖힘(검사기 `IsSquash`·공중 예외와 같은 규칙).
