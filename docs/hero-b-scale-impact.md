# 주인공 B 크기(키 ~80px) 전환 — 규격 변경 영향 정리

작성 2026-10-25. 상태: **결정 완료 (2026-10-25)** — 4절 참고. 1단계(규격 반영) 진행.
근거: 새 화풍 파일럿 `NEWIMAG/StylePilot2/` 의 B(1배 bbox 52×80px, 포니테일 포함), 현재 코드·맵 수치 조사.
계획서 `docs/px32-conversion-plan.md` 의 32px·PPU32·640×360 기본 틀은 **유지**한다. 바뀌는 것은 주인공(과 적) 크기 규격뿐이다.

---

## 0. 한 줄 요약

- 아트를 2.5칸(80px)으로 키워도 **콜라이더를 아트만큼 키우지 않으면** 맵·점프·함정은 거의 그대로 쓸 수 있다.
- 추천: 콜라이더를 **0.75 × 1.875칸(24×60px)** 으로 적당히 키운다. 머리카락·포니테일·상자는 판정 밖에 둔다.
  - 이 크기로 기존 4개 스테이지가 그대로 통과된다.
  - 다만 화살 2곳의 명중 여부가 바뀐다(밸런스 확인 필요).
- 진짜 큰 일은 **적 아트**다. 지금 고블린(키 32px)은 새 주인공 무릎 높이라, 적도 새 화풍·새 크기로 다시 만들어야 어울린다.

## 2. 콜라이더 선택지

| 안 | 콜라이더 | 맵 | 함정 판정 | 문제 |
|---|---|---|---|---|
| ① 유지 | 0.6875 × 1.4375 | 변경 없음 | 변경 없음 | 화살이 머리·몸 위쪽을 **지나가도 안 맞음**(보이는 것과 판정 불일치) |
| **② 중간 (추천)** | **0.75 × 1.875** | 변경 없음 (최소 통로 2칸 > 1.875) | 화살 2곳 명중으로 바뀜 | 머리 꼭대기·포니테일은 판정 밖(관대한 판정, 플랫포머 관례) |
| ③ 아트 전체 | 1.0 × 2.4 | **stage_01 필수 통로(2칸) 막힘**, stage_04 해머 방(3칸)에서 해머와 겹침 | 화살 3곳 이상 바뀜 | 맵 재작업 + 점프 재조정 |

### ② 의 근거 수치
- **통로**
  - 필수 경로에서 가장 낮은 통로는 stage_01 x8–12, 높이 2칸이다(스폰 (2,1) → 골 (21,1) 사이 바닥길).
  - 1.875 이면 0.125칸(4px) 여유가 있다. 2.0 은 딱 맞아서 끼임 위험이 있다.
- **해머 방**
  - stage_04 천장 슬롯 (15,8)·(20,8) 아래 여유는 3.0칸이다.
  - 콜라이더 1.875 + 해머 0.7 = 2.575 라 들어간다. ③(2.4+0.7=3.1)은 안 들어간다.
- **1칸 폭 수직 통로** stage_04 x=18: 폭 0.75 < 1 이라 통과한다. 다만 아트(1.6칸)가 벽에 겹쳐 보인다(시각만).
- **점프**
  - 점프 물리는 칸 단위라 그대로 둔다. 최고점 3칸이고, 맵의 올라서기 구간(+1~+3, 대시 포함 +4~5)이 유지된다.
  - 몸이 커서 "점프가 낮아 보이는" 느낌은 생긴다. 바꿀지는 결정 필요(아래 D3).
- **스폰·리스폰**
  - 스폰은 칸 중심 + 발 −0.755 이고, 콜라이더 바닥은 유지한다.
  - 위로만 커지고, 스폰 칸들 위는 모두 열려 있어서 문제없다.

### ② 에서 바뀌는 화살 판정 (명중 = 서 있는 주인공에게 맞는지)
화살 높이는 서 있는 바닥면 기준이다. 판정 구간은 현재 0~1.4375, ②는 0~1.875 이다.

| 위치 | 화살 높이 | 현재 | ② |
|---|---|---|---|
| stage_03 (1,7) 오른쪽 벽 | 1.5 | 거의 스침(0.01) | **명중** |
| stage_04 (23,2) 오른쪽 벽 | 1.5 | 거의 스침 | **명중** |
| stage_04 (30,3) 왼쪽 벽 | 2.5 | 빗나감 | 빗나감 (포니테일만 통과, 판정 밖) |

→ stage_03·04 가 조금 어려워진다. 전환 후 SmokeProbe + 플레이테스트로 확인하고, 필요하면 balance-track 에서 조정한다.

## 3. 영역별 영향 (② 기준)

### 3.1 주인공 — 반드시 바뀜
- `Px32Rules` 주인공 규격: 셀 64 → **96**, 키 48 → **80**(머리 윗선 ~72), 폭 ≤32 → **≤56**.
  - 피벗(하단 중앙), 프레임 수, fps 는 그대로다.
- 주인공 시트 8종을 B 화풍으로 재생성한다.
  - Idle 6 · Run 8 · JumpStart 2 · Fall 2 · Land 3 · Dash 4 · Hit 2 · Death 6.
  - 지금 시트는 버린다.
- `Px32HeroWiring`: 새 콜라이더 0.75 × 1.875. 바닥 유지 → offset.y = −0.755 + 0.9375 = **0.1825**.
  - 메뉴를 다시 실행하면 클립 재배선, Visual, 콜라이더가 갱신된다.
- `GroundCheck` 박스 0.74 × 0.12 는 폭 0.75 와 맞아 그대로 둔다(확인만).
- `DashGaugeUI` 오프셋 (0.85, 0.55) "머리 옆" → **(1.0, 1.7)** 정도로 올린다.
- `PlayerEffects.effectScale` 1.81 은 몸 키 기준이라 이펙트 단계(6단계)에서 재조정한다.

### 3.2 카메라 — 소폭
- 추적 오프셋 TargetOffset y **0.5 → 1.0**.
  - 지금은 화면 중심이 발 위 1.255 이다. 새 키에서는 몸 중간(발 위 ~1.25)이 화면 중심보다 아래로 쏠리지 않게 올린다.
- 640×360 · PPC · 줌은 유지한다. 주인공이 화면 높이의 22%라 위아래로 각각 약 4.4칸이 보인다.
  - 좁게 느껴지면 줌아웃 대신 **맵 쪽에서 낙하 구간을 짧게** 하는 쪽을 권장한다(PPC 정수 배율 유지).
- `BuildCameraController.GlideTarget` 가 TargetOffset 을 무시하는 기존 동작은 그대로다(언급만).

### 3.3 맵 — 데이터 변경 없음, 규칙 추가
- 기존 4개 스테이지는 ②에서 **그대로 통과**한다.
- 맵 에디터·`MapAuthoringValidator` 에 **통행 높이 규칙**을 추가한다(경고).
  - "주인공이 지나는 가로 통로는 높이 ≥ 2칸".
  - 지금은 높이·점프 검사가 전혀 없다.
- 계획서의 맵 비율 규칙(h ∈ {14,18}, 25×14 / 32×18)은 그대로다.
  - 다만 h=14 맵은 주인공 키 대비 세로 여유가 5.6배로 줄어든다. 위층 구조는 3~4칸 간격을 권장한다.
- 아트가 1칸 폭 통로·낮은 천장에서 벽에 겹쳐 보이는 건 시각 문제다. 필요하면 맵 디자인에서 피한다.

### 3.4 적 — 아트 재제작 필요 (가장 큰 작업)
- 지금 적 키: 고블린·임프 32px, 스켈레톤·기사 48px, 오크 64px. 새 주인공(80px) 옆에서 너무 작고, 화풍(판타지 도트)도 다르다.
- 새 적 키 제안. 주인공 80 기준이고, 셀은 32 배수다.

| 적 | 키 | 셀 | 콜라이더(제안) |
|---|---|---|---|
| 고블린 | 48 | 64 | 0.75 × 1.25 |
| 임프(공중) | 44 | 64 | 1.0 × 1.0 |
| 스켈레톤 | 72 | 96 | 0.75 × 1.75 |
| 엘리트 기사 | 84 | 96 | 0.875 × 2.0 |
| 오크 | 96 | 128 | 1.25 × 2.25 |

- **AI 경로는 영향 없음**: NavGrid 는 개체를 1칸으로 보고, 키·폭 검사가 없다. 키네마틱 이동이다.
- 적 콜라이더는 함정 판정에만 쓰인다. 크기를 바꾸면 **돌파율이 바뀐다** → 전환 후 스테이지별 돌파율을 비교한다(5단계 리뷰 권장 사항과 같은 작업).
- 큰 적은 2칸 통로(stage_01)에서 머리가 천장에 겹쳐 보인다. AI 는 통과하므로 시각 문제일 뿐이다.
- 5단계에서 만든 배선(`Px32EnemyWiring`, 클립 재배선, 발 위치 −0.5)은 그대로 다시 쓴다. 셀 규격만 `Px32Rules` 에서 바꾼다.

### 3.5 함정·타일·배경
- 함정 판정은 모두 "콜라이더 겹침"이고, 주인공 키를 가정한 코드는 없다. 위 화살 표만 영향받는다.
- 함정·타일은 32px 칸 그대로다. 화풍만 새 팔레트로 다시 그린다(6단계 함정, 3단계 타일 재생성).
- 배경은 7단계(1:1) 계획 그대로이고, 새 팔레트 톤으로 그린다.

### 3.6 코드에서 손댈 곳 (예상)
| 파일 | 변경 |
|---|---|
| `Editor/Px32/Px32Rules.cs` | 주인공 셀 96, 적 셀 표 |
| `Editor/Px32/Px32HeroWiring.cs` | 새 콜라이더 상수 |
| `Editor/Px32/Px32EnemyWiring.cs` | (필요 시) 적 콜라이더 맞춤 옵션 |
| `Editor/Px32/PixelArtSheetValidator.cs` | 폭·높이 규격 표 반영(있다면) |

| `SampleScene` | vcam TargetOffset, DashGaugeUI 오프셋 |
| `docs/px32-conversion-plan.md` | 2.2 규격표, 5·6단계 범위 |
런타임 게임 로직 변경은 **없다**(점프·이동·AI·함정 코드 그대로).

## 5. 진행 순서
1. **규격 반영 (완료 2026-10-25)**
   - `Px32Rules`: 주인공 셀 96, 적 셀 64/96/128, 구 규격 `GetLegacySheetSpec`(과도기), 팔레트 구+v2 합집합(`NEWIMAG/palette_v2.txt`).
   - CI `sprites32`: 구 규격으로 통과하는 시트는 "교체 대기" 경고.
   - `Px32HeroWiring`: 콜라이더 0.75×1.875, vcam TargetOffset.y 1.0, DashGaugeUI (1.0, 1.7). 시트 셀이 96이 아니면 중단 → **씬은 새 아트 입고 때 한 번에 바뀐다**.
   - `MapAuthoringValidator`: 통행 높이 2칸 미만 바닥 칸 경고.
   - 계획서 2.2 규격표.
   - 적 콜라이더 맞춤은 4번(적 입고) 때 `Px32EnemyWiring` 에 추가한다.
2. 주인공 B 8종 시트 생성 → 가져오기 → `Px32 주인공 연결` 재실행 → CI·스모크·플레이 확인.
3. 새 팔레트 확정 → 타일 재생성.
4. **적 5종 재디자인 (완료 2026-10-28)** — 컨셉 `NEWIMAG/EnemyConceptV2`(독성 초록+보라, 팔레트 v2 에 9색 추가) 승인 → 시트 20장 `NEWIMAG/Px32EnemyV2` → `Px32 적 연결`(3.4 콜라이더 표).
   돌파율: 스테이지 1~3 기준선과 시드별 결과·시간 동일(검증 AI 는 고블린 아키타입만 쓰고 NavGrid 경로로 이동).
5. **함정 3종 재디자인 (2026-10-29)** — 컨셉 `NEWIMAG/TrapConceptV2`(크림슨 주인공 편, 상태: Dud 녹·회색 / Critical 붉은 가열 / Beneficial 금·왕관, 팔레트 v2 에 금·녹 6색) 승인 → 파츠 `NEWIMAG/Px32TrapV2` → `Px32 함정 연결`(기존 Parts 경로 덮어쓰기·PPU 32, 슬롯 마커 4방향·봉인 타일 팔레트 연결). 가시는 매립 덮개 위 받침(Base, order 13) 추가, 화살 Visual 1배. 판정·칸 크기 불변.
6. **이펙트·월드 UI (2026-10-30)** — 컨셉 `NEWIMAG/FxUiConceptV2` 승인 → 최종 `NEWIMAG/Px32FxV2` → `Px32 이펙트·UI 연결`.
   주인공 대시·피격·사망·리스폰 + 착지 먼지(신규), 적 처치 연기(신규 `AgentKillFx`, `AgentHealth.OnAgentKilled`),
   픽셀 링 게이지(대시 32px·쿨다운 24px, 9단계 프레임), 함정 상태 파티클 텍스처, 골 깃발 프리팹, HUD 함정·철거 아이콘.
   → 배경(7단계).
