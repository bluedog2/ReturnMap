## 1단계 — 모델 시트 (GPT, 사용자 승인)

`NEWIMAG/Px32HeroRef/` 에 출력한다. 승인된 것은 커밋해서 이후 모든 요청서의 참조로 쓴다.

1. **턴어라운드 4면**: 앞 · 3/4 오른쪽(게임 화면, 승인 Idle 0 기준) · 옆(오른쪽) · 뒤. 셀 128, 주인공 96px, 승인 Idle 팔레트, 서 있는 기본 자세(팔 내림, 가방은 허리춤).
   - 3/4 면은 승인 Idle 0 을 마스크 부분 수정해서 만든다(몸·얼굴 픽셀 보존). 나머지 3면은 GPT 가 새로 그리고, 머리 꼭대기·어깨·벨트·발바닥 행을 3/4 면과 맞춘다.
2. **가방 시트**: 앞 · 옆 · 3/4 · 입 벌림, 각각 허리춤 크기와 손에 든 크기. 허리춤 걸이(끈·고리) 포함.
3. **소매·손 디테일**: 팔 내림 · 허리에 손(C) · 앞으로 뻗음 · 뒤로 흔듦 4종. 소매가 손목까지 오고 장갑이 바로 이어지는지 보여주는 확대용.

검수: 설정표 항목별 통과/실패를 `validation.json` 에 기록 + 3배 확대 눈 검사 + 행 정렬 측정. 재요청은 최대 2회.

## 프레임 기준 — 부드러움 우선 (2026-11-06 사용자 결정)

원칙:
1. **동작 시간은 게임 감각이 정한다.** 지금 시간(대시 0.21초·착지 0.2초·피격 0.25초 등)은 그대로 둔다. 같은 시간 안에서 장수와 fps 를 올려 부드럽게 한다. 조작이 늦어지는 일은 없다.
2. 모든 동작 **최소 8fps**, 빠른 동작은 **20fps 이상**.
3. 장수는 동작마다 다르다. 같은 장수로 통일하지 않는다.
4. 장수가 늘면 GPT 가 디테일을 틀릴 위험도 는다. 그래서 키 포즈를 먼저 승인받고, 사이 프레임은 그 키 포즈를 참조해 그린다. 가방·소매는 평행이동으로 재사용한다.

## 3단계 — 나머지 시트

Run → JumpStart → 상승·꼭대기·낙하 → Land → Dash → Hit → Death 순서. 장수·fps 는 「프레임 기준」 표.
- 각 시트: GPT 원본 → **ASF 후처리**(정렬·크기 통일·팔레트 잠금·검사) → 설정표 검수 → 사용자 승인.
- 가방은 1단계 픽셀을 프레임마다 평행이동만 한다. 움직임은 엉덩이를 1~2px 늦게 따라간다.

## 4단계 — 전환 애니 (`docs/animation-plan-v6.md` 표 그대로)

장수·fps 는 위 「프레임 기준」 표를 따른다. 꺼내기는 허리춤 가방을 떼어 손에 드는 동작이다.

## 5단계 — 연결

FSM·컨트롤러 배선, `Px32Rules` 스펙, CI·스모크·플레이 프로브. 전환 애니는 그림만 바꾸고 입력은 절대 늦추지 않는다.
